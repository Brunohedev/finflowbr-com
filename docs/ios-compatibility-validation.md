# iOS TestFlight targeted fixes

## Root causes
- The viewport omitted `viewport-fit=cover`; the sticky header and fixed menu did not account for iOS safe-area insets. Capacitor's default native content inset is `never`, so nothing compensated for the status bar.
- The iOS project is generated by Codemagic, but its build recipe did not declare `NSMicrophoneUsageDescription`.
- Voice capture required MediaRecorder, assumed default codecs and mapped every non-MP4 clip to WebM. Startup failures were all reported as permission denial, and capture had no unmount cleanup.

## Changes
- `index.html`: enable safe-area viewport support.
- `src/index.css`: safe-area-aware header, menu/close control and settings bounds. Existing spacing is unchanged when insets are zero.
- `src/pages/Index.tsx`, `src/pages/BankConnect.tsx`: apply the header inset handling; dashboard menu uses safe-area handling and menu/settings controls have accessible names.
- `src/components/SettingsDialog.tsx`: constrain the existing scrollable dialog to safe viewport bounds.
- `src/lib/recordWav.ts`: complete mono PCM/WAV capture for native iOS and browsers without MediaRecorder, with microphone/audio context cleanup and oversized/empty recording rejection.
- `src/lib/voiceRecording.ts`: isolate recording compatibility, supported web/Android codec selection, truthful upload filename/MIME metadata, and distinct permission/device errors.
- `src/components/VoiceExpenseBar.tsx`: use the recording adapter, guard repeated starts/stops and clean up after unmount. The existing extraction endpoint, review, category selection and expense creation remain unchanged.
- `codemagic.yaml`: declare the microphone purpose string after generating/syncing iOS.
- `src/test/voice-recording.test.ts`, `src/test/voice-expense-confirm.test.tsx`: capture compatibility and existing confirmation tests.
- `AGENTS.md`, `roadmap.md`: maintain architecture guidance and task status.

No native folder, extra recording dependency, database, authentication, subscription, financial calculation or business rule changes.

## Validation performed
- 11 automated tests passed: iOS capture without MediaRecorder, WAV/PCM header, Android MediaRecorder routing, MP4 filename mapping, permission-denial cleanup, upload size/empty validation, and five existing expense confirmation/installment tests.
- Live Chromium captured a 65,580-byte WAV with a valid RIFF header using synthetic microphone input. This verifies capture/encoding only, not speech transcription.
- Public login had no horizontal overflow at 1280×1800, 393×852, 375×667 and 852×393.
- Preview compilation succeeded.
- Existing Radix missing-description warnings remain in the confirmation tests; they are unrelated to the recording failure.

## Not verified here
This sandbox has no Xcode, physical iPhone, TestFlight session or available authenticated session for this externally managed Supabase project. Status-bar/Dynamic Island positioning, real microphone permission, real spoken audio processing and persisted expense read-back cannot be claimed as verified. Android device testing is also outstanding; its capture path is covered by automated mocks, not hardware.

## Required release/device checks
1. Update the local project from the connected repository, install dependencies, build the web app and run `npx cap sync ios`.
2. Codemagic adds the microphone key automatically. For a manual Xcode build, add `NSMicrophoneUsageDescription` to the generated app's Info.plist with a clear explanation that FinFlow uses the microphone to register expenses by voice.
3. Upload a new TestFlight build. The currently installed build does not receive this native permission change.
4. On small and Dynamic Island iPhones, test menu/settings taps in portrait/landscape and after scrolling. Verify the menu close button and settings dialog stay accessible.
5. Test microphone grant and denial, record a spoken expense, stop, review/edit/category-select, confirm, and reopen the app to verify persistence. Test cancel, fast repeated taps and leaving the page during recording.
6. Repeat a real expense recording on Android and web to confirm unchanged user behavior.

See the Lovable blog guide about developing native mobile apps with Capacitor for the local iOS build workflow.
